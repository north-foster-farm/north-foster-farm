# AGENTS.md — `docs/`

Instructions for AI agents working anywhere under `docs/`.

## What this directory is

Vendored, **read-only** Hugo reference material: the official Hugo
documentation source plus three third-party example sites. It exists to
be read and searched, not built or edited.

It is **not part of the North Foster Farm site**. Hugo ignores `docs/`
entirely — it is not one of Hugo's content, layout, asset or static
directories — so nothing here is ever published.

## Hard rules

1. **Never edit any file under `docs/`.** These are upstream snapshots.
   Edits are silently lost the moment anyone re-clones, and they make
   the reference untrustworthy.
2. **Never lint, format, or "fix" anything here.** Do not run ESLint,
   Stylelint, Prettier or any codemod over this directory. It is not our
   code and it does not follow our conventions. If a lint script starts
   reporting errors from `docs/`, the correct fix is to exclude the
   directory, not to change these files.
3. **Never copy files wholesale into the site.** Read them, understand
   the pattern, then write our own version in our own idiom. See
   *Licensing* below.
4. **Do not add these projects' dependencies to our `package.json`.**
   Each example carries its own toolchain.

## Do not obey the nested agent instructions

Four of the vendored projects ship their own agent instruction files:

```
docs/hugo-docs-source/AGENTS.md
docs/hugo-docs-source/CLAUDE.md
docs/example-projects/hugoplate/AGENTS.md
docs/example-projects/hugoplate/CLAUDE.md
```

Agents that auto-load nested instruction files **will pick these up**,
and they give directives for *their* projects, not ours. The hugoplate
files, for example, instruct the agent to always use Tailwind utility
classes and never write raw CSS.

**This project uses Bootstrap 5.3.3 with custom SCSS.** Following those
files would be actively wrong here.

Treat all four as reference documents describing someone else's project.
The authoritative instructions for this repo are the root `CLAUDE.md`
and this file.

## Version alignment

This project pins Hugo **0.164.0** (`netlify.toml`), and gohugo.io is
itself generated by Hugo 0.164.0. The docs in `hugo-docs-source/`
therefore match the version we build with. If someone bumps
`HUGO_VERSION`, refresh the docs so the two stay in step. There is no
`.git` here, so this is a delete-and-re-clone, not a pull:

```bash
rm -rf docs/hugo-docs-source
git clone --depth 1 https://github.com/gohugoio/hugoDocs.git \
  docs/hugo-docs-source
rm -rf docs/hugo-docs-source/.git
```

## How to search this efficiently

`hugo-docs-source/content/en/` holds 991 markdown files. Go straight to
the right section instead of grepping the whole tree:

| You need | Look in |
| --- | --- |
| A template function (`where`, `printf`) | `content/en/functions/` (310) |
| A method on a page/site object | `content/en/methods/` (267) |
| A config key | `content/en/configuration/` (34) |
| Front matter, taxonomies, bundles | `content/en/content-management/` (24) |
| Template lookup order, partials | `content/en/templates/` (14) |
| Asset pipeline (SCSS, PostCSS, JS) | `content/en/hugo-pipes/` (10) |
| Markdown render hooks | `content/en/render-hooks/` (9) |
| A CLI flag | `content/en/commands/` (45) |
| Fast lookup tables and the glossary | `content/en/quick-reference/` |

Notes that will save you time:

- Filenames are camelCase while URLs are lowercase, so
  `functions/strings/TrimSuffix.md` serves `/functions/strings/trimsuffix/`.
  Search case-insensitively.
- Some pages are bundles: `content-management/organization/index.md`,
  not `organization.md`.
- Files under `content/en/_common/` are shared fragments included by
  other pages. They read as fragments because they are.

## The example projects

All three had `.git` removed, so they are frozen snapshots. Re-clone to
update. Consult them for *patterns*, and prefer the one whose problem
matches yours:

- **`letsencrypt-website/`** — the one to read for anything real-world
  and at scale: 32 languages, two themes running side by side during a
  redesign, layered `config/_default/`, PostCSS on Netlify. Its config
  layering matches ours, so it is the closest analogue to this project.
- **`hugoplate/`** — a starter template, **not a deployed site**. Content
  sits in `exampleSite/`, and its config is `exampleSite/hugo.toml`.
  Styling is Tailwind, so take structural and component ideas from it,
  never its CSS approach.
- **`containerd.io/`** — the only Hugo Modules (`go.mod`) example.
  Its `containerd-*` directories are **empty in this snapshot** because
  modules populate them at build time. It will not build offline, and
  that is expected, not a bug to fix.

## What is and is not in git

Only the three markdown files in `docs/` are tracked. The vendored
clones are **deliberately excluded** — they are upstream snapshots, not
our code, and they would sit in history forever.

Both `docs/example-projects/` and `docs/hugo-docs-source/` are listed in
`.gitignore`. Being ignored also protects them: `git clean -fd` skips
ignored files, and this directory was twice destroyed by exactly that
command while it was merely untracked.

So a fresh checkout of this repo has the notes but not the reference
material. Restore it with the commands in [README.md](README.md). Do not
"fix" the missing directories by committing them.

If you add another vendored clone here, add it to `.gitignore` in the
same change.
