# Hugo reference material

Local, offline Hugo reference gathered 2026-07-30. None of this is part
of the site build — it is here to read, grep and copy patterns from.

> [!IMPORTANT]
> If you are an AI agent, read [AGENTS.md](AGENTS.md) first. These are
> read-only upstream snapshots, and some of them ship their own agent
> instructions that do not apply to this project.

## `hugo-docs-source/`

A shallow clone of [gohugoio/hugoDocs](https://github.com/gohugoio/hugoDocs),
the source repo behind <https://gohugo.io>. 8.2 MB, 991 markdown files.

This replaced an HTML scrape of the live site, and the swap was
verified rather than assumed: of the 789 pages in the site's sitemap,
788 have a matching markdown file here. The only one that does not is
`/categories/`, which Hugo generates automatically as a taxonomy
listing — it is not authored content. Nothing is lost, and markdown is
far better to search than rendered HTML.

The docs live under `content/en/`:

| Section | Pages |
| --- | ---: |
| `functions/` | 310 |
| `methods/` | 267 |
| `quick-reference/` | 163 |
| `commands/` | 45 |
| `configuration/` | 34 |
| `content-management/` | 24 |
| `host-and-deploy/` | 15 |
| `templates/` | 14 |
| `shortcodes/` | 12 |
| `hugo-pipes/` | 10 |
| `render-hooks/` | 9 |

Because it is a real Hugo project, `hugo server` inside that directory
renders the docs for offline browsing.

Its `.git` was removed, so this is a frozen snapshot like the example
projects. Updating means deleting the directory and re-cloning — see
[Restoring the clones](#restoring-the-clones).

The docs match the Hugo version we build with — this project pins
0.164.0, and gohugo.io is itself generated by 0.164.0.

## `example-projects/`

Three real Hugo projects, picked for **architectural variety** rather
than three versions of the same idea. Most large Hugo sites on GitHub
are CNCF documentation sites running the Docsy theme and look nearly
identical inside, so these deliberately come from different niches.

`.git` has been removed from each, so they are frozen snapshots.
Total on disk: 158 MB.

| Project | Size | Last updated | Why it is here |
| --- | ---: | --- | --- |
| `letsencrypt-website/` | 152 MB | 2026-07-29 | Large real-world non-profit site |
| `hugoplate/` | 3.1 MB | 2026-07-25 | Modern Tailwind + pnpm starter |
| `containerd.io/` | 3.1 MB | 2026-07-30 | Hugo Modules and versioned docs |

### `letsencrypt-website/`

From [letsencrypt/website](https://github.com/letsencrypt/website).
The site behind <https://letsencrypt.org>, and the most useful of the
three for seeing how a serious, long-lived Hugo site is organised.

- **32 content languages**, translations as sibling directories under
  `content/`, UI strings in `i18n/`.
- **Two themes side by side** (`themes/le-2021`, `themes/le-2025`) —
  how they staged a full redesign without a big-bang rewrite.
- Layered config in `config/_default/hugo.toml`, the same pattern this
  repo uses.
- PostCSS pipeline, deployed on Netlify — again close to our setup.
- 1,232 markdown files, so also a useful look at Hugo under load.

### `hugoplate/`

From [zeon-studio/hugoplate](https://github.com/zeon-studio/hugoplate).
A starter template, not a deployed site — worth knowing before reading
it. Included because it is the closest structural match to a small
marketing site like ours, with a very different styling approach from
everything else here.

- **Tailwind CSS** rather than Bootstrap, built through pnpm.
- The repo root is the theme; demo content is in `exampleSite/`, with
  config at `exampleSite/hugo.toml`.
- Multilingual-ready, though the bundled demo ships English only.
- A good source of component and partial structure.

### `containerd.io/`

From [containerd/containerd.io](https://github.com/containerd/containerd.io).
The smallest project, included for one reason: it is the only one of the
three using **Hugo Modules** (`go.mod`) to pull in content and theme
dependencies instead of vendoring them.

- Demonstrates versioned documentation via `containerd-*` directories
  mounted through the module system.
- Those directories are **empty in this snapshot** — modules populate
  them at build time, so this project will not build offline.
- Uses the older `config.toml` naming rather than `hugo.toml`, handy for
  recognising both conventions in the wild.

## `hugo-sites-on-github.md`

A wider survey of large, popular Hugo sites on GitHub, each verified as
genuinely Hugo by reading its file tree rather than trusting topic tags.
Also covers:

- **E-commerce** — why there is no healthy open-source Hugo store
  ecosystem, and what people actually do instead (Snipcart, Shopify Buy
  Button, Stripe Payment Links).
- **Tailwind CSS** — maintained Hugo + Tailwind starters with their
  Tailwind versions, plus why the most-starred search result is stale.
- **Tailwind UI** — it is a paid product that cannot be redistributed,
  with free MIT-licensed alternatives.
- **Checked and ruled out** — 17 repos confirmed *not* to be Hugo, with
  the generator each one actually uses.

## Restoring the clones

Only the markdown notes in this directory are tracked in git. Both
`example-projects/` and `hugo-docs-source/` are gitignored, so a fresh
checkout will not have them. To rebuild from scratch:

```bash
mkdir -p docs/example-projects && cd docs/example-projects

git clone --depth 1 https://github.com/letsencrypt/website.git \
  letsencrypt-website
git clone --depth 1 https://github.com/zeon-studio/hugoplate.git
git clone --depth 1 https://github.com/containerd/containerd.io.git

rm -rf letsencrypt-website/.git hugoplate/.git containerd.io/.git
```

The `.git` removal is deliberate: it keeps the snapshots read-only and
saves space. Re-clone to update them.

And for the docs themselves, same pattern:

```bash
git clone --depth 1 https://github.com/gohugoio/hugoDocs.git \
  docs/hugo-docs-source
rm -rf docs/hugo-docs-source/.git
```
